# 底层实现：训练引擎

训练一个模型时，上层代码通常只有几行：

```cpp
optimizer->ZeroGrad();

auto predictions = model->OpValue(images);
auto loss = CrossEntropyLoss(predictions, labels);

loss.Backward();
optimizer->Step();
```

但这几行背后存在一条完整的数据链路：张量保存输入和参数，算子执行前向计算并记录依赖，损失从计算图末端发起反向传播，优化器最后读取梯度并更新参数。

```text
输入张量
   ↓
模型与算子 ──→ 前向结果
   ↓              ↓
计算图         损失函数
   └──── 梯度反向传播
                  ↓
               参数更新
```

本书以我实现的 [Zero](https://github.com/Ismantic/Zero) 为基础，拆开这几行训练代码，说明一个深度学习训练引擎如何从底层组成。

## 一个教学用训练引擎

Zero 使用 C++17 编写，同时支持 CPU 和 CUDA。它参考 PyTorch 的动态图设计，但不追求覆盖完整的框架功能，也不以替代现有训练框架为目标。

它的定位是教学：用一套规模可控、能够实际运行的代码，把张量、自动微分、算子、模型、优化器和 GPU kernel 放在一起观察。读者看到的不只是各部分的接口，还包括它们之间的数据所有权、形状约束和执行顺序。

Zero 可以在 CPU 上训练 MNIST，也可以使用同一套基础设施在 GPU 上训练字符级 GPT。二者承担不同作用：MNIST 验证最基本的训练闭环，GPT 则展示同一套引擎扩展到注意力、融合算子和大规模参数后的样子。

## 张量不只是一组数值

前向计算从 `Tensor` 开始。一个张量除了数据，还要保存形状、步长、数据类型和所在设备。`View` 与 `Transpose` 可以共享底层存储，却以不同的元数据解释它；CPU 和 CUDA 张量则由不同的内存上下文负责分配。

张量还承担自动微分中的身份。前向表达式产生的结果需要记住由哪个算子生成、依赖哪些输入，以及梯度应该写入哪个共享槽。存储共享、视图关系与梯度共享必须分别处理，否则一次看似普通的浅拷贝或转置就可能破坏反向传播。

## 算子连接前向与反向

每个可微算子都实现两件事：根据输入计算结果，以及根据上游梯度计算各输入的梯度。例如乘法 \(z=x\cdot y\) 的反向规则为：

$$
\frac{\partial L}{\partial x}
=\frac{\partial L}{\partial z}y,
\qquad
\frac{\partial L}{\partial y}
=\frac{\partial L}{\partial z}x
$$

Zero 在前向执行算子的同时动态建立计算图。调用 `Backward()` 后，引擎先得到拓扑顺序，再逆序执行每个算子的局部反向规则。一个张量经过多条路径影响损失时，来自各路径的梯度还要累加到同一个梯度槽。

同一个算子接口可以派发到 CPU 或 CUDA kernel。设备差异被限制在数值实现和内存管理中，计算图仍然使用相同的节点和反向规则。

## 从参数到训练循环

`Parameter` 是需要优化的张量，`Module` 将参数和子模块组织成模型。Linear、MLP、Embedding、LayerNorm 和 Attention 都建立在张量算子之上，而不是绕开自动微分单独实现训练逻辑。

优化器持有参数集合。`ZeroGrad()` 清理上一轮梯度，`Step()` 根据 SGD 或 AdamW 等规则修改参数。更新过程必须关闭建图，否则参数更新本身也会进入下一轮计算图。

由此，一次训练迭代形成闭环：

```text
Parameter
   ↓ 前向
Loss
   ↓ Backward
Gradient
   ↓ Optimizer::Step
新的 Parameter
```

## 从 MNIST 到 GPT

MNIST 中的 MLP 已经会经过矩阵乘法、bias 广播、激活函数、交叉熵、反向传播和参数更新，因此足以验证训练引擎的基础结构是否正确。

GPT 没有改变这套基本过程，而是提高了对引擎的要求：Embedding 引入索引操作，多头注意力引入批量矩阵乘法和因果遮罩，LayerNorm 与 FFN 产生更多中间张量，GPU 执行则需要考虑 kernel 启动、内存池、归约和算子融合。

所以本书不是从一个简单框架跳到另一套 GPT 框架，而是沿着同一套训练引擎逐步增加模型和设备复杂度。

## 本书的阅读顺序

全书由七篇文章组成，并按照训练系统的依赖关系排列：

1. **自动微分**：从链式法则进入动态图、拓扑遍历和梯度累加。
2. **张量与内存**：解释形状、步长、存储共享、视图和设备内存。
3. **算子与反向传播**：实现前向、反向、广播、矩阵乘法与设备派发。
4. **模型与参数**：将可训练参数组织成 Linear、MLP 等模型结构。
5. **优化器**：完成梯度清理、裁剪、参数更新和学习率调度。
6. **GPU 执行**：进入 CUDA kernel、内存池、cuBLAS 和异步执行。
7. **GPT 训练**：将前面的组件组合成字符级语言模型训练流程。

前三篇解释训练引擎的计算基础，模型与优化器完成可运行的训练闭环，GPU 和 GPT 则展示这套设计如何继续扩展。

## 阅读范围

本书关注训练引擎怎样工作，不负责完整介绍神经网络理论，也不会逐项复刻 PyTorch API。公式用于确定实现规则，代码用于展示这些规则如何落到张量形状、内存布局和算子接口上。

读完以后，读者应该能够沿着一次训练迭代，解释前向数据如何产生计算图、损失梯度如何传回参数，以及同一套执行过程如何从 CPU 上的 MNIST 扩展到 GPU 上的 GPT。
